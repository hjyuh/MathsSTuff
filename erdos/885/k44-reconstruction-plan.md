# EP885 K_{4,4} reconstruction plan (no Bremner PDF)

Date: 2026-04-26

Goal: produce at least one explicit `K_{4,4}` certificate (4 deltas, 4 `N`
values, full factor-pair matrix) without using Bremner's 2019 paper text.

This note assumes the local conventions from:

- `erdos/885/known-constructions.md`
- `erdos/885/algebraic-lifting-notes.md`
- verified `K_{4,3}` seed JSON in `erdos/885/results/*certificate.json`

and uses the three-row elliptic-curve mechanism attributed to Jimenez-Urroz.

## 0. Notation snapshot (local)

Rows are differences `d_i > 0`.  Columns are values `N_j > 0`.  Incidence is

```text
d in D(N)   <=>   exists a>=1 with N = a(a+d)
```

Equivalently, with `x = 4N`, every incidence gives an integer square

```text
y^2 = d^2 + x,     y = 2a + d.
```

Thus a `K_{r,s}` witness is exactly a matrix of squares `y_{ij}` satisfying

```text
y_{ij}^2 = d_i^2 + x_j  (1<=i<=r, 1<=j<=s),   x_j = 4N_j.
```

Rational solutions are enough: scaling by a common denominator yields an
integer certificate (see Section 1 of `algebraic-lifting-notes.md`).

## 1. Three-row elliptic curve (Jimenez-Urroz form)

Fix three rows `d_1,d_2,d_3`.  Put

```text
A = d_1^2 - d_2^2
B = d_1^2 - d_3^2
```

For a candidate column `x`, define the anchored square

```text
lambda := d_1^2 + x = y_1^2.
```

Then the three row conditions are

```text
lambda          = y_1^2
lambda - A      = y_2^2
lambda - B      = y_3^2
```

and these square triples are controlled by the full-2-torsion curve

```text
E(A,B):  W^2 = X(X-A)(X-B).
```

Given a triple-square column, the point

```text
P = (X,W) = (lambda,  +/- y_1 y_2 y_3)
```

lies on `E(A,B)`.  Conversely, the standard 2-descent criterion says that a
rational point `P` is in `2E(Q)` iff `X`, `X-A`, `X-B` are all rational squares
away from 2-torsion exceptions.  In practice:

- columns for three fixed rows correspond to points in `2E(Q)`;
- sums of known column-points stay in `2E(Q)`, so they keep the first three
  square constraints automatically.

This gives a concrete column-generation mechanism for *fixed* three rows:
enumerate points in the subgroup generated by known columns, map
`X -> lambda -> x -> N`, and verify.

## 2. Turning three rows into four rows (the `K_{4,4}` step)

To get a `K_{4,4}` from a known `K_{4,3}` seed, the cleanest path is
`algebraic-lifting-notes.md` Test 4:

Input:

- a verified `K_{4,3}` seed with rows `{d_1,d_2,d_3,d_4}` and columns
  `{x_1,x_2,x_3}` (with `x_j = 4N_j`);
- choose an ordered triple `(d_1,d_2,d_3)` as the elliptic anchor;
- treat `d_4` as an extra square filter.

Extra row condition: for a point `P=(X,W)` on `E(A,B)`, the implied column is

```text
x = X - d_1^2,
```

and the 4th row requires

```text
d_4^2 + x = square  <=>  X + (d_4^2 - d_1^2) = square.
```

So the `K_{4,4}` search loop is:

1. Build `E(A,B)` from three chosen rows.
2. Convert each known seed column `x_j` into a rational point
   `P_j = (d_1^2+x_j, +/-y_{1j}y_{2j}y_{3j})` on `E(A,B)`.
3. Enumerate group combinations of the `P_j` (or, better, compute a basis for
   the subgroup they generate).
4. For each candidate point `P`, take `X(P)` and test whether
   `X(P) + (d_4^2 - d_1^2)` is a rational square.
5. If yes, recover `x = X - d_1^2`, `N = x/4`, clear denominators, and verify
   the full `K_{4,4}` with `scripts/verify_biclique.py`.

This is computational algebra, not brute force over `N`: the expensive part is
elliptic arithmetic, and the filter is a single extra-square check.

### Concrete worked setup: forum `K_{4,3}`

From `erdos/885/results/forum-triple-certificate.json` / `algebraic-lifting-notes.md`:

```text
deltas d = [36, 468, 692, 1028]
N values N = [79200, 227205, 1258560]
x = 4N = [316800, 908820, 5034240]
```

Take anchor triple `(d_1,d_2,d_3)=(36,468,692)`, and filter row `d_4=1028`.
Then

```text
A = 36^2 - 468^2 = -217728
B = 36^2 - 692^2 = -477568
E: W^2 = X(X+217728)(X+477568)
extra-square constant: d_4^2 - d_1^2 = 1055488
```

The three seed columns yield three explicit points in `2E(Q)`:

```text
x=316800:  X=36^2+x=318096,   W = 564*732*892
x=908820:  X=910116,          W = 954*1062*1178
x=5034240: X=5035536,         W = 2244*2292*2348
```

Any integer combination `aP1+bP2+cP3` gives a candidate `X`.  The `K_{4,4}`
test is simply:

```text
X + 1055488  is a rational square?
```

Low-height note: an exact-arithmetic probe over combinations
`|a|,|b|,|c| <= 10` for this specific anchor triple did not produce a new
column beyond the known three.  This is not evidence of impossibility; it only
means that if the forum seed extends via this mechanism, it likely happens at
higher height or with a different triple/seed.

## 3. Explicit parameterization/search scheme (no elliptic library required)

The three-row elliptic curve can be accessed through an explicit conic
parameter and a quartic model.  This gives a *directly testable* integer scan.

Fix the same ordered triple `(d_1,d_2,d_3)` and define `A,B` as above.  Start
from the conic `y_1^2 - y_2^2 = A` and parametrize it by a free parameter
`p in Q*`:

```text
y_1 = (p^2 + A)/(2p)
y_2 = (p^2 - A)/(2p)
```

Then `lambda = y_1^2`, and the third row requires `y_3^2 = lambda - B`.  After
clearing denominators,

```text
(2p y_3)^2 = Q_3(p) := p^4 + (2A - 4B)p^2 + A^2.
```

Now add a 4th row `d_4`.  Put `K = d_4^2 - d_1^2`.  The extra condition
`lambda + K = y_4^2` becomes

```text
(2p y_4)^2 = Q_4(p) := p^4 + (2A + 4K)p^2 + A^2.
```

Therefore a `K_{4,4}` column for the four rows is obtained by finding a
nonzero rational `p` such that **both** `Q_3(p)` and `Q_4(p)` are rational
squares.  For an integer scan, take `p in Z\\{0}` and check:

```text
Q_3(p) is a perfect square integer
Q_4(p) is a perfect square integer
```

Then compute

```text
lambda = y_1^2
x = lambda - d_1^2
N = x/4
```

and clear denominators by scaling with `L = 4|p|` (safe parity/integrality), or
more generally by taking `L` to be twice a common denominator of all rational
`d_i` and `y_{ij}` in the candidate witness.

This search has a built-in modular sieve: for small primes `q`, eliminate `p`
classes where `Q_3(p)` or `Q_4(p)` is a nonsquare mod `q`.  It is also easy to
parallelize across `p` ranges.

## 4. What Bremner data would collapse this reconstruction

Any of the following would short-circuit most of the work:

1. One explicit numerical `K_{4,4}` witness from Bremner (four `N` values and
   their four common deltas), ideally with factor pairs `(a,a+d)` shown.
   This can be verified immediately with `scripts/verify_biclique.py` and then
   converted into the local `(d_i,x_j,y_{ij})` square-shift format.

2. The specific elliptic curve model Bremner uses for `k=4`:
   whether it is directly an `E(A,B)` plus a 2-cover (extra-square constraint),
   or a different but isomorphic genus-1 model.

3. A concrete parameterization of the four deltas (or of `A,B,K`) and at least
   one rational point/generator used to prove infinitude (i.e., the actual
   "seed point" whose multiples produce new columns).

4. The denominator-clearing / integrality lemma he uses to turn rational
   points into integer `N_i` and integer deltas cleanly (this affects how
   quickly we can search for small integer examples).

With (1) alone we can stop "reconstructing" and start "explaining": fit the
observed witness into `E(A,B)` and identify which of the mechanisms above is
actually the one Bremner used.
